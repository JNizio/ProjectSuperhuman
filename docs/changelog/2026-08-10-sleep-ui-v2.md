# 2026-08-10 — Sleep UI v2

## Purpose
Expose the sleep engine in a clearer user-facing way without mixing measured source data with interpretation.

## Implemented
- Added a Recorded / Interpreted view switch.
- Recorded view presents source-reported sleep values.
- Interpreted view presents the confidence-aware engine output.
- Added a Smart Sleep Insight card with the engine headline, explanation, priority and component scores.
- Added a Data Confidence card showing confidence for duration, stages, efficiency and interpretation.
- Reworked the recent-history card as Personal Pattern so the baseline concept is easier to understand.
- Improved spacing, hierarchy and alignment across the Sleep screen.
- Increased header/card consistency and tightened typography.
- Corrected the top-left back control alignment so the glyph sits centrally inside its touch container.
- Kept the existing Health Connect sync flow and sleep architecture diagram intact.

## UX principles
- Source data is never disguised as an estimate.
- Interpretation is presented as a second layer rather than replacing the source view.
- Confidence is visible without overwhelming the user.
- The UI should remain useful even when stage coverage is incomplete.
- Avoid unnecessary technical language in the primary experience.

## Next UI direction
Use the reconstructed sleep blocks directly in the architecture timeline, then introduce personal-baseline comparisons and cross-module evidence only when enough longitudinal data exists.
